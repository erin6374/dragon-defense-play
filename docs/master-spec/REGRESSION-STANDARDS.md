# Regression and acceptance standards — 0.1.0
## Evidence ladder
Record requirement ID, train, exact candidate SHA, build, fixture/seed, platform, renderer, resolution/preset, test script+version, result, artifacts/hash, time (UTC and Eastern), reviewer, limitations. Source-read != test run; test definition != pass; historical != exact candidate; software rendering != native; assisted != unassisted; CI != art approval. A failed or missing gate cannot be overwritten by a success on a different SHA.

## Exact Preview 11 gate (observed implementation)
qa/park13-release-gate.mjs requires exact 40-char candidate SHA for every evidence object. Source: 165 expansion records, 122 original parcels, 33825 footprint checks, 322560 surface checks, zero conflicts, 165 lifecycle targets. Browser: exactly enabled/disabled runs, both school and 122 parcels, on 165/off null, live meteor damage then repair zero, after repair delay zero meteors/fragments, no errors. Native: real RTX3060 not SwiftShader/llvmpipe/software/WARP, Balanced, cap45, 1280×720, matched traverse and bombardment A/B, >=300 samples, focused/completed, no context loss, each >=40 average FPS, enabled p95 <=40ms, enabled avg >=90% baseline and p95 <=120% baseline. Visual: named reviewer approves north, central, south, campus, street seams, damage-repair evidence. Package: exact SHA, archive SHA256, launcher smoke, version 5.5.0-integration.11, rollback verified. Missing gate => not ready. These are candidate-specific source thresholds, not blanket approval for every platform.
 
## Reproduce existing QA
On checked-out exact candidate, serve over local HTTP; use packaged PLAY-PREVIEW.cmd / tools/windows-preview-server.py for Windows telemetry. qa/README documents Playwright Core and FFmpeg libx264; set PLAYWRIGHT_MODULE to absolute index.mjs, QA_BROWSER_CHANNEL=chrome or QA_BROWSER_EXECUTABLE, run node qa/motion.mjs http://127.0.0.1:8765/ for motion; qa-output/motion. Use workflow commands for each branch's scripts, not guessed arguments. Capture Windows with CAPTURE-WINDOWS-PERFORMANCE.cmd, preserve CSV and analyze using python tools/analyze-windows-performance.py <csv> --json. Host rows repeat stale browser FPS, so only browser rows used for FPS; focused visible tab and fresh heartbeat vs RAF stalls tracked. No GPU utilization claim when null. Verify every artifact against exact workflow SHA; independently inspect video frames and reports, not just status. Test time = actual test time, report time separate. 
## Staged execution
A small edit: syntax, pure contract, one targeted check. B candidate: browser changed path, fixed-seed visual A/B and short motion. C settled integration: all affected existing full suites, artifacts CRC, license/FBX hashes, package. D release: physical native heavy scene, active human 15-wave play, art and platform-specific acceptance. Use affected-test matrix; do not rerun expensive workflows for status-only edits. Regression failure blocks release, retain failing fixture and root cause. Never alter tests just to hide a failure; change expectation only with documented requirement decision.
